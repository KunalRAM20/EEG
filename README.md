# EEG Research Web Application

This repository contains a research-focused EEG analysis web application.

Repository: [KunalRAM20/EEG](https://github.com/KunalRAM20/EEG)

The primary workflow is:

1. Upload a genuine EEG recording.
2. Validate file safety and recording compatibility.
3. Analyze the recording in fixed windows.
4. Produce window-level probabilities and candidate model-evidence events.
5. Generate an AI draft report.
6. Require reviewer validation before final JSON/PDF export.

This is a research prototype, not a clinical diagnostic or treatment system.

---

## 1. What this project does

The project provides an EEG-only analysis path in the web app while keeping non-EEG modalities as contextual records.

Implemented capabilities:

1. Accepts EEG uploads in EDF, BDF, CSV, TXT, and NPY.
2. Extracts recording metadata (format, sampling rate, samples, channels, duration).
3. Enforces file-safety checks (extension allowlist, size checks, signature checks for supported types).
4. Uses generated storage names and file hashing for provenance.
5. Supports long recordings by slicing into overlapping windows for analysis.
6. Performs per-window quality checks.
7. Abstains on unsuitable windows.
8. Aggregates positive windows into candidate model-evidence events.
9. Preserves immutable AI draft report and separate reviewer-edited version.
10. Exports approved report data to JSON and PDF from one structured schema.
11. Generates interconnected **synthetic composite cases** on demand, so the
    full multi-modal pipeline can be demonstrated without a real linked cohort.

---

## 1.1 Why composite cases exist

No public cohort in this repository contains one patient with EEG, ECG, MRI,
X-ray, reports, history and daily routine together. The three cohorts are
disjoint and are deliberately never joined by identity. To demonstrate the
end-to-end pipeline anyway, the app can assemble an *internally coherent
composite* from real files:

1. One real annotated moment in one real SeizeIT2 participant is chosen as the
   anchor. EEG, ECG, EMG and movement are cropped from that participant's own
   recordings at that same second, so those four are genuinely same-person.
2. The MRI donor is selected from ds004199 by matching the anchor's recorded
   seizure lateralization and localization against the donor's recorded lesion
   hemisphere and lobe. The donor is always reported as a different person,
   with the match criteria attached.
3. The chest X-ray is the single local OpenI case, always flagged as an
   unrelated cohort and excluded from severity scoring.
4. Age, history, medication and daily routine are derived from those real
   anchors by documented rule, and tagged `derived` in the provenance table.

Composite cases are watermarked as synthetic on every screen, in the report
text, and in the exported JSON and PDF. They describe no real person.

Use the **Select random data** button on the Upload EEG page. Generation takes
roughly 15-25 seconds because it reads several real EDF recordings. The seed is
shown on the case page and regenerates that exact case.

## 2. What model is used

Current deployed model behavior:

1. Trained from Bonn/UCI-derived single-channel EEG features.
2. Produces calibrated seizure-class probability.
3. Uses a 5-level EEG model evidence scale derived from probability bands.
4. Does not assess clinical severity, urgency, treatment, or diagnosis.

Important compatibility rule:

1. Prediction requires a single-channel compatible signal and sufficient sample length for the trained segment size.
2. Multi-channel uploads are accepted and stored, but analysis abstains unless a compatible single-channel path is available.

## 5. Data sources and what is actually used

Used directly by the deployed prediction model:

1. Bonn/UCI-style EEG feature path.

Available but not active model inputs:

1. SeizeIT2 assets (review, and the anchor for composite cases).
2. MRI sample data (donor rows and one local subject's volumes).
3. OpenI X-ray sample data.
4. Uploaded ECG, imaging files, and documents.

What is actually materialized on disk:

1. Bonn/UCI CSV: complete (11,500 chunks).
2. SeizeIT2: **5 of 125** participants have real EEG/ECG/EMG/movement payloads
   (sub-002, sub-004, sub-007, sub-010, sub-013). The other 120 are git-annex
   pointer stubs of about 104 bytes and cannot be analyzed.
3. ds004199: the 170-row clinical table is complete and real, but only
   `sub-00043` has downloaded imaging volumes. It is a paediatric cohort
   (ages 3-13), which is why a composite never adopts a donor's age.
4. OpenI: one case (`CXR1151`), a normal chest X-ray from a general radiology
   collection.

Interpretation:

1. For an uploaded recording, non-EEG assets are contextual-only and are not
   fused into prediction output.
2. For a generated composite case, ECG, movement, semiology and the matched MRI
   row do contribute — but only through the transparent, itemised composite
   severity rule layer described in section 5.2, never through the model.

## 5.1 Known limitation: the model does not transfer to SeizeIT2

Measured locally, and stated plainly because a composite case will otherwise
look broken:

| Data | Ictal probability | Non-ictal probability |
|---|---|---|
| Bonn/UCI (in-distribution) | about 0.98 | about 0.01 |
| SeizeIT2 behind-the-ear (out-of-distribution) | about 0.01 | about 0.01 |

The deployed classifier separates Bonn ictal from non-ictal segments cleanly,
but returns roughly 0.01 for **every** window of resampled behind-the-ear
wearable EEG, seizure and background alike. It has no discrimination on that
recording type.

Consequences:

1. A composite case will show EEG evidence Level 1 even when the anchor is a
   real, annotated, video-confirmed seizure. That is the expected result of the
   domain shift, not a fault in the pipeline.
2. The composite severity layer is what carries such a case, because the ECG,
   semiology and MRI evidence are real and unaffected.
3. Fixing this requires training or fine-tuning on SeizeIT2-style data, which
   needs a proper cohort. It is deliberately out of scope here.

## 5.2 Composite severity (multi-modal, rule-based)

The calibrated EEG evidence tier is unchanged and remains the only
model-derived number. Beside it, composite cases also receive a transparent
additive grade whose every term is reported with its weight, its measurement
and the reason it fired:

| Term | Source | Max |
|---|---|---|
| EEG evidence tier | existing calibrated tier, `(level - 1) x 0.5` | 2.0 |
| Ictal heart-rate rise | R-peak analysis of the participant's own ECG | 1.0 |
| Recorded seizure burden | counted from the real annotation files | 1.0 |
| Impaired awareness | annotated `eventType` | 0.5 |
| Motor / hyperkinetic semiology | annotated `eventType` | 0.5 |
| Structural MRI finding | matched donor's clinical row | 0.5 |

A maximal EEG tier alone reaches 2.0 and therefore cannot by itself produce a
maximal composite grade; corroboration is required. Terms whose input is
missing score zero and are flagged, so a low grade caused by absent data is
never presented as a reassuring result. This is decision support, not a
validated clinical severity scale.

## 6. End-to-end data flow

1. User uploads EEG through web form.
2. Server validates file and stores safely.
3. Recording parser extracts metadata and loads signal.
4. App checks model compatibility.
5. Compatible recording is split into overlapping windows.
6. Each window receives quality assessment.
7. Suitable windows are scored by the model.
8. Unsuitable windows are abstained with explicit reason.
9. Positive windows are grouped into candidate model-evidence events.
10. AI draft report is generated.
11. Reviewer approves/modifies/rejects report.
12. Approved report can be exported as JSON/PDF.

## 7. Setup from a clean environment

### 7.1 Prerequisites

1. Windows with Python 3.13 available.
2. Internet access for package install.

### 7.2 Install dependencies

From project root:

```powershell
python -m pip install -r requirements.txt
```

### 7.3 Train or refresh model artifacts

One command, from the project root:

```powershell
python scripts/train.py
```

This checks dependencies, ensures the dataset is present, extracts cached
features, trains and compares models, and prints recording-held-out metrics.
To run only the training step:

```powershell
python -m src.models.train
```

Expected artifacts in models_store include best_model.joblib, metrics.json, and feature_names.json.

## 8. Run and use the application

### 8.1 Start the app

```powershell
python webapp/app.py
```

Open:

1. http://127.0.0.1:5000

### 8.2 Primary user workflow

1. Open Upload EEG.
2. Select EEG file in EDF, BDF, CSV, TXT, or NPY format.
3. For CSV/TXT/NPY, provide sampling rate.
4. For multi-channel numeric files, provide explicit channel names.
5. Submit upload.
6. Open case page and review metadata.
7. Click Analyze EEG.
8. Open report page and review:
   - overall probability,
   - EEG evidence level,
   - window-level analysis table,
   - candidate model-evidence event table.
9. Validate report as reviewer.
10. Export approved JSON/PDF.

### 8.3 Generating a linked demo case

1. Open Upload EEG.
2. Scroll to "Or generate a linked demo case".
3. Choose a target profile:
   - `any` — any real annotated moment,
   - `high` — prefer impaired-awareness motor seizures,
   - `low` — prefer seizure-free background windows.
4. Optionally enter a seed to reproduce an exact case.
5. Click Select random data. Generation takes about 15-25 seconds.
6. Review the case page: anchor event, measurements taken from that
   participant, matched MRI donor, and the full provenance table.
7. Analyze, then review the report's composite severity derivation.
8. Validate and export as with any other case; both exports carry the synthetic
   watermark and the provenance block.

On successful upload:

1. Case page shows recording metadata:
   - format,
   - sampling rate,
   - sample count,
   - channel count.

On successful analysis:

1. Report page shows:
   - EEG seizure-class probability,
   - EEG model evidence level,
   - generated draft report text,
   - window-level analysis table,
   - candidate model-evidence events.

On unsuitable or incompatible data:

1. UI displays abstention-safe messages rather than fabricated output.
2. Incompatible recordings remain stored for review.

On review and export:

1. Reviewer decision appears in report page.
2. Export buttons are enabled only for approve/modify decisions.
3. JSON and PDF represent the same structured facts.

## 10. Verification checklist (recommended)

Use this checklist to verify end-to-end behavior:

1. Upload a valid single-channel TXT EEG with required sample length.
   Expected:
   - compatibility true,
   - report created,
   - probability and level displayed.

2. Upload a longer single-channel signal.
   Expected:
   - multiple windows appear,
   - candidate events table appears when threshold crossings occur.

3. Upload multi-channel NPY without channel names.
   Expected:
   - validation error or abstention due to channel policy.

4. Upload EDF and BDF test files.
   Expected:
   - parser reads metadata,
   - case page shows format and channels.

5. Validate report then export JSON and PDF.
   Expected:
   - both exports available only after reviewer approval,
   - timeline/event facts included in JSON schema.

## 12. How to inspect rendered data for correctness

1. In case view, verify upload metadata matches source file.
2. In report view, verify per-window timestamps are increasing and aligned.
3. Verify abstained windows include clear reason text.
4. Verify candidate events aggregate adjacent positive windows.
5. Download JSON and inspect analysis.window_level_analysis and analysis.candidate_model_evidence_events.
6. Confirm PDF reflects the approved reviewer content.

## 13. Security and safety controls in place

1. CSRF protection for form submissions.
2. File extension and size checks.
3. Signature checks for selected file types.
4. Generated upload storage names.
5. SHA-256 file hashing and metadata capture.
6. No automatic prediction on incompatible data.
7. Reviewer approval required for final export.
8. Immutable AI draft preserved separately from reviewer edits.

## 14. Current limitations

1. Deployed model remains single-channel Bonn/UCI-style, and has **no
   discrimination** on SeizeIT2 behind-the-ear EEG (see section 5.1).
2. For uploaded recordings, non-EEG modalities are contextual only.
3. Composite severity applies to generated composite cases only, and is a
   transparent rule layer rather than a validated clinical scale.
4. Only 5 SeizeIT2 participants and 1 MRI subject's volumes are materialized
   locally; the rest are git-annex pointer stubs.
5. This is not a clinical validation package.
6. UI event visualization is tabular (not yet a full interactive timeline chart).

## 15. Troubleshooting

If model unavailable warning appears:

1. Re-run `scripts/train.py`.
2. Check models_store contains metrics.json and best_model.joblib.

If EDF/BDF parse fails:

1. Ensure mne is installed from requirements.
2. Re-test with known valid EDF/BDF files.

If exports are blocked:

1. Open report validation page.
2. Submit approve or modify decision.

If tests fail unexpectedly:

1. Re-install dependencies.
2. Re-run targeted failing test module with -v.
